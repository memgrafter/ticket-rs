# tk create ergonomics: no --link/--dry-run, frontmatter flags, metachar doc

## Design

Scope: low-severity tk-create gaps observed while creating linked research
tickets (2026-09-24). None block work; each costs re-discovered workaround time
per session.

### Item 1 — long descriptions with shell metacharacters are fragile via -d
Backticks / `$` / `()` / `<>` in markdown break when passed inline:
```sh
# fails: bash runs command substitution before tk sees anything
tk create "t" -d 'Use `_matching_staging_key()` here'
# workaround that works (but is NOT in `tk create --help`):
printf '%s' 'Use `_matching_staging_key()` here' > /tmp/desc.md
tk create "t" -d "$(cat /tmp/desc.md)"
```
Overlaps: tr-fpht (backticks), tr-kv5m (`--description-file`, the real fix).
Test case: `--help` output documents the file-based workaround (grep for
`$(cat` or `description file` in help text).

### Item 2 — no flags for links/deps; bidirectional linking is hand-edited
Today, creating two linked tickets requires:
```sh
ID=$(tk create "A" -d "..." | tail -1)          # e.g. tr-aaaa
# then hand-edit the OTHER ticket's frontmatter:
#   links: []  ->  links: [tr-aaaa]
# and hand-edit A's frontmatter too:
#   links: []  ->  links: [tr-bbbb]
```
Proposed:
```sh
tk create "A" --link tr-bbbb      # sets links: [tr-bbbb] in A's frontmatter
tk link tr-aaaa tr-bbbb           # adds the link BOTH ways
```
Test cases:
| # | command | expected |
|---|---|---|
| 1 | `tk create "A" --link tr-bbbb` (tr-bbbb exists) | A's frontmatter `links: [tr-bbbb]` |
| 2 | `tk create "A" --link tr-zzzz` (does not exist) | explicit error, A not created (or created-unlinked — pick one, document) |
| 3 | `tk link a b` when a already links b | idempotent, no duplicate entry |
| 4 | `tk link a b` | `links` in both a and b contain the other |
| 5 | `tk link` with self `tk link a a` | explicit error |

### Item 3 — no dry-run / parse preview
`tk create` writes immediately; there is no way to see the parsed frontmatter
or which sections will render (see tr-s3yr) before the file exists:
```sh
tk create "T" -t feature -p 2 --tags a,b -d "$(cat desc.md)" --dry-run
# expected: prints the frontmatter as it will be written + the list of
# sections tk show will render vs hide, and writes NO file
```
Test cases:
| # | condition | expected |
|---|---|---|
| 1 | valid inputs + --dry-run | parsed frontmatter printed; no new file in .tickets/ |
| 2 | --dry-run with a description that would fail arg parsing | explicit error, no file |
| 3 | --dry-run then real create | same file contents as dry-run predicted |

### Item 4 — ID not predictable in scripts
The ID is generated inside `create` and only discoverable from stdout, so
"create two linked tickets in one shot" is awkward (see Item 2). Related:
`tk create --id <id>` (caller-supplied, validated) would make scripted pairs
deterministic. Test case: `tk create --id tr-xxxx "t"` creates with exactly
that ID; a collision errors.

### Suggested single PR
"create ergonomics": `--link`, `--dry-run` with parse echo, `--help` text
documenting the file-based description workaround. (Items 1-doc + 2 + 3.)

### Acceptance Criteria
- [ ] `--link` (create) and `tk link a b` (both ways, idempotent) — cases above
- [ ] `--dry-run` prints parsed frontmatter + render plan, writes nothing
- [ ] `--help` documents the write-to-file description workaround
- [ ] (stretch) `--id` for deterministic scripted creation
